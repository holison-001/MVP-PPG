# MVP PPG 펌웨어 개발계획

최신 초안은 [v0.4 개발계획](MVP-PPG_펌웨어_개발계획_초안_v0.4_20261025.docx)입니다. 2026년 10월 25일 개정으로 PC GUI 화면과 조작 규칙을 추가했습니다. v0.3의 명령·응답 규격, PC 명령행 제안, 분주 오차 조건과 사용률 68.84%를 유지합니다. 현재 이 폴더는 개발계획 문서를 보관하며 펌웨어 또는 PC 수신기 구현 코드는 포함하지 않습니다.

## v0.4 GUI 구성

- **연결과 상태:** 포트 선택·연결, 장치 정보와 MCU 상태, 원본 기록 상태, 화면 일시정지를 각각 표시합니다.
- **실시간 수집:** Green·IR·Red의 원시 ADC 파형, 센서 상대 시각, 세션·epoch, 시작·정지, 독립된 손실·오류 계수를 표시합니다.
- **측정 설정:** 검증된 프로파일·LED 전류·ADC 허용값만 적용하며 미적용 변경과 실제 config_id를 구분합니다.
- **기록과 검증:** 새 폴더에 rx.bin·session.json·summary.json을 보존하고, 오프라인 검사와 오류·복구 기록을 제공합니다.

시작은 IDLE·유효 설정·저장 준비 조건을 만족할 때만 허용합니다. 화면 일시정지는 그래프만 멈추고 원본 기록은 계속합니다. 측정 정지는 STOPPED 확인 뒤 완료로 표시하며, 연결 단절·강제 종료는 정지 미확인으로 남깁니다. GUI와 CLI는 같은 포트를 동시에 열지 않습니다. 문서의 화면은 모의 데이터를 이용한 시안이며 실제 장치 통신의 구현 완료를 뜻하지 않습니다.

## v0.3 추가 내용

| 코드 16진수 | PC 명령 | 목적 |
|---|---|---|
| 01 | PING | 연결 확인과 토큰 응답 |
| 02 | GET_INFO | 프로토콜과 빌드 및 지원 기능 조회 |
| 03 | GET_STATUS | 상태와 세션 및 오류 통계 조회 |
| 04 | GET_CONFIG | 실제 검증된 측정 설정 조회 |
| 10 | SET_CONFIG | IDLE에서 측정 프로파일과 LED 및 ADC 설정 적용 |
| 20 | START | 확인한 설정 ID로 새 수집 세션 시작 |
| 21 | STOP | 수집 정지와 마지막 데이터 및 종료 통계 확인 |
| 30 | CLEAR_STATS | IDLE에서 조회용 누적 통계 초기화 |

제안 규격은 COBS와 CRC16을 사용하며 DATA와 명령·응답·이벤트를 구분합니다. 기존 DATA 최대 110바이트와 UART 250000 baud를 유지하고, 제어 프레임은 최대 62바이트로 둡니다. 요청 ID를 이용한 중복 실행 방지, START와 STOP의 데이터 순서, 센서 복구와 재연결, 수신 오류 처리 및 버퍼 산정도 포함합니다.

명령 번호와 필드 및 처리 시간은 구현할 초안입니다. 프로파일별 LED 전류와 ADC 허용 범위, 실제 SRAM 사용량과 최대 부하 통신은 구현·실물 시험으로 확정해야 합니다.

## 보레이트와 전송률 계산

USART1 입력 클럭이 명목 48 MHz이고 USART 프리스케일러 1, 오버샘플링 16배(`OVER8=0`), `BRR=192=0x00C0`이면 `48,000,000 ÷ 1 ÷ 192 = 250,000 bps`로 **명목 분주 오차는 0%**입니다. 실제 발진기 오차와 온도 드리프트 및 PC USB-UART 어댑터의 250000 baud 지원은 별도로 검증합니다. [ST 공식 USART 드라이버](https://github.com/STMicroelectronics/stm32c0xx-hal-driver/blob/main/Inc/stm32c0xx_ll_usart.h)

센서 샘플률 오차 +2%와 초당 200개 DATA 프레임을 반영한 169,004.8 bps에 최대 62바이트 제어 응답을 초당 5개 보내는 3,100 bps를 합하면 **172,104.8 bps**입니다. `172,104.8 ÷ 250,000 × 100 = 68.84192%`이므로 소수 둘째 자리 사용률은 **68.84%**입니다. 복구 이벤트가 없는 정상 상태 기준이며 지연 후 FIFO 배출과 복구 이벤트 부하는 별도 시험합니다.

## PC 명령행 프로그램 제안

PC에서 사용할 실행 파일 이름을 `ppg`로 제안합니다. 아래는 인터페이스 제안이며 아직 구현된 명령은 아닙니다.

```text
ppg ports
ppg info --port COM5
ppg status --port COM5
ppg config show --port COM5
ppg config apply --port COM5 --file settings.json
ppg capture --port COM5 --config settings.json --duration 600 --out run01
ppg stop --port COM5
ppg stats clear --port COM5
ppg validate --in run01
```

`capture`가 포트와 수집 파일을 소유하며, 기간 만료 또는 Ctrl+C 한 번으로 같은 연결에서 STOP과 종료 통계를 확인합니다. 기존 측정이 실행 중이면 임의 재시작하지 않습니다. 별도 `stop`은 포트가 해제된 뒤 장치에 남은 측정을 정지하는 복구용입니다. `rx.bin`에 받은 UART 바이트를 그대로, `session.json`에 설정과 세션 정보를, `summary.json`에 오류·손실과 정지 확인 결과를 보관합니다. COM5는 예시이며 LED 전류와 ADC 설정은 실물 검증 후 입력합니다.
